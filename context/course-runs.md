**Course tests:** `python3 submission/course.py NAME [--tag T --repeat N --view]` runs `sim.sh --world` into the main checkout's `runs/` (shared by every worktree, [[worktrees]]) and scores from HIM's `trace.npz` (truth) and the run's `events.jsonl` ([[sim-run-logs]]): outcome, pass, time, path, end error, closest, contacts (movers included), recoveries, drift; criteria are in the world's `NAME.yaml`. Distances use `course.geom_distance`: MuJoCo 3.3 sometimes returns 0 between a capsule (a foot) and a cylinder (a pillar, the wheelchair) 0.6 m apart, with nearest points off a geom or not as far apart as it says; such a result is replaced by the exact distance (before Nov 3 every atrium "pillar contact" was this). Held-out worlds: `python3 submission/generate_world.py --seed N` writes a random walled hall (`worlds/heldout_N`), kept only if the robot's footprint can reach the goal; generate and commit one before running it, and run it once, to test code nobody tuned against it. `course.py` doesn't build: run `submission/build.sh` after changing code, or the run uses the old image while `run.json`'s diff shows the new code. `--events RUN` lists a run's events with sim times; `--compare [WORLD]` lists runs by world and tag (give a branch's runs tags of their own). Builds and runs wait for each other, one at a time per computer (the sim lock, [[worktrees]]). It exits 1 if any run didn't succeed or failed its criteria; verdicts reject non-finite measurements and limits.

**Run length:** a run lasts HIM's 5 s start-up balance, then the world's `max_time_s` plus 12 s (`STARTUP`; Nav2 sends the goal about 6 s in) whatever happens, then 5 s of Holosoma balance after our container stops: our image never exits on its own. After the goal GR00T stands, its heading creeping about 0.1°/s; Holosoma's takeover can shift the robot a few cm, so judge a planned move at its `move_done` event, not the trace's end (`course.py`'s end error uses the trace's last frame).

**Run folders:** `sim.sh --output DIR` (every course run) writes `run.json` (git commit, branch, dirty flag with the diff in `git.diff`, HIM's commit, image id, `G1_TASK_COMMAND`; `course.py` runs also add the computer's memory each second, `host_memory`) and the scene HIM loaded, minus HIM's G1, in `scene/`. After each run, and with `course.py --prune [RUN]`: HIM's viewer output goes, and every `trace.npz` but the newest 2 of each world loses its compiled scene (47 MB) and thrash data, only when the scene rebuilt from `scene/` and HIM's G1 at that commit matches the trace's exactly; scoring needs only `time` and `qpos`. Whole runs are never deleted: that's a separate decision. Cut-off traces are skipped ([[sim-deadline-stops]]).

**Watching** ([[feedback-watching-runs]]): `sim.sh` opens HIM's live browser viewer by default (`--no-view` to skip) and starts the run at once (it writes the flag HIM's page's Start would); Start on the page plays from the first frame. `course.py --view` prints each run's URL and closes the viewer 10 s after HIM's report, so one is up at a time; it warns about viewers still up (about 700 MB each) and memory pressure. HIM's live viewer can't show movers ([[nav2-sim]]). `course.py --replay RUN` serves any run's replay, stripped ones included, with the movers walking ([[sim-run-logs]]); replays don't take the sim lock. HIM's first viewer use downloads Three.js; on a Python.org Python that needs `SSL_CERT_FILE` from `certifi`.

**Routes** (`--route NAME_OR_FILE` from `submission/routes/`, or `--waypoint X Y [HEADING]` per point, `--laps N`; format in `harp/route.py`): saved as the run's `route.yaml` and passed as `G1_TASK_COMMAND` `{"route": ...}` to `course_goal`, which moves on only after Nav2 reports a point reached with its own last pose within 0.5 m of it (otherwise it sends the point again, a `stale_success` event, until the point's timeout); a rejection, failure or timeout (240 s per point) ends the route and latches zero for the session ([[approach-stop]]). The end error is from the last point and the verdict uses the route's own `criteria` (none: no verdict; `max_speed_near_people_mps` allowed). The run is sized from its `max_time_s`, or 0.15 m/s along its legs plus 10 s per point. Baseline: `rectangle` on `one_box`, one lap, 4/4 points, 73.6 s, closest 0.59 m, 0 contacts or recoveries (`runs/2026-10-28_09-30-12Z_sim_one_box_route`). Recording a route: [[waypoint-recorder]].
