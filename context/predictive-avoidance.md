**Selection:** `course.py --avoidance predictive` adds `avoidance` to task JSON. `entrypoint.sh` selects one `/cmd_vel_nav` → `/cmd_vel` filter; default is `approach_stop`. Predictive mode rejects hardware, missing-world and planned-move combinations. Nav2 owns route planning in the image; HIM owns motors.

**Observation:** stamped TF compensates robot/head motion; input receipt and sensor timestamps must stay fresh. `PredictiveAvoidance.process_scan` (no ROS types) filters floor/self returns and runs the tracker, so offline harnesses run the same pipeline. Returns inside a recently seen moving track's predicted disc (its learned size + 3 cm) are claimed for it first, so a walker beside a wall or people abreast stay moving objects. The remaining long or thin surfaces (over 1.4 m, or ≥0.9 m long and ≤0.2 m thick) become static structure: 0.36 m tiles on a fixed grid, IDs from 10⁹, zero velocity, never matched against objects. Compact objects are fitted from their visible side seen from the sensor (centre one radius behind the nearest returns, radius = farthest return + 6 cm), which removed a 0.1 m sensor-facing bias and halved position error. A constant-velocity Kalman filter (1 m/s² acceleration noise, Joseph-form update) gives velocity in a few scans and an uncertainty from its covariance. Joint Hungarian assignment uses age-independent miss costs. Merged returns split using tracks seen within 0.35 s. Each object learns its own size (fast for its first 8 views, then grow slowly, shrink fast); a later view over 1.35× that size, or a split, updates position but not velocity until two consistent scans pass, so a column never inherits a passing walker's motion (that had driven the robot through a column). Every observation stays occupied; capacity overflow stops motion.

**Occlusion:** tracks coast 2.5 s. Nearby expired occupancy is retained as measured surface cells, cleared by rays passing beyond, footprint clearing, or transfer into fresh occupancy (whole tracks or single cells). Wall tiles never enter this memory: they cannot approach unseen and no ray passes beyond a wall. This is occupancy memory, not identity through occlusion.

**Planning:** three velocity blocks over a 4 s forecast, measured initial motion, delayed acceleration-limited rollout. One soft-constrained ranking over every candidate, standing included: task terms (rollout progress, tracking, continuity, committed side, retreat penalty) + body penetration (deepest discounted depth, not duration) + tradeable comfort-margin intrusion + a fixed preference for a certifiably clear path. Comfort spread grows with time and with each object's speed (`Config.speed_spread`, 0.1). Discount 2 s, comfort weight 2 (chosen by a crowd sweep). The previous request is kept unless another is clearly better. Robust safety terms take the worse of a nominal and a slow-sidestep walker model (`Config.lateral_pessimism` 0.6), since native G1 sidesteps vary with gait phase (fit: forward delay ≈0.25 s, gains 0.84/0.60, lateral rms error 0.10 m/s); this beat no robustness on a harness with variable sidesteps (contacts 14→9, no wall contacts, faster mixed runs). Wall tiles and remembered surfaces go into a per-cycle 5 cm distance field (body and body+uncertainty layers); slow tracked objects (<0.08 m/s: columns, standing people) join it as a second group whose comfort clearance shrinks with forecast growth; moving objects keep exact swept checks. Unreachable objects are pruned first; the 160-object limit applies after pruning. All candidates are ranked with the nominal walker model and the best 24 (plus standing and the previous request) re-ranked robustly, halving planning time. Urgency (unramped escape) comes from approaching objects or an actual body overlap with fixed geometry, never from mere proximity to a wall. An existing comfort intrusion may be repaid over 2 s, a ramped walker's launch. SLSQP refines only certifiably clear choices, capped near 80 ms. `harp/SFM_NMPC_REFERENCE.md` records the independent mathematical adaptation, not an upstream plugin port.

**Model limits:** constant-velocity prediction does not assume cooperation and cannot foresee a turn; the speed spread only shapes preferences. Collision inflation of track uncertainty is capped (`Config.max_collision_uncertainty`): bounded risk, not a reachable-set guarantee. Forward and lateral response gains differ (native G1: sidestep ≈0.2 m/s). Standing plus an alert cannot prevent an incoming object hitting a stopped robot; least-intrusion motion is a ranking under the same forecast, not a guarantee.

**Integration:** 5 Hz lower-priority filter, 0.15 s planning deadline, zero on stale/malformed input or planning failure. Route success idles; failure latches zero. `/harp/obstacle_alert` is a JSON signal, not an installed horn. Results: `follow`, `yield`, `evade`, `blocked` (standing ranked best); alert whenever the chosen path is not certifiably clear.

**Checks:** 127 local tests (live DDS needs `ROS_LOCALHOST_ONLY=1` and a nonzero `ROS_DOMAIN_ID`), four planar MuJoCo scenarios, and `submission/crowd_harness.py` (real tracker/memory/route/MPC on ray-cast LiDAR with a planar walker plant; see [[native-crowd]]). Full Docker/Foxy/Nav2/HIM validation requires the external harness and remains unverified here.
