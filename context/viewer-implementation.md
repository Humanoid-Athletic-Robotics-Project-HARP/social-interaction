Viewing policy and links: [[unified-viewer]]. Implementation is in `viewer/`; user setup belongs in `viewer/README.md`.

- `server.py` is a standard-library hub. Optional producers keep their own Python environments; importing the hub must not import ROS, MuJoCo, audio drivers or model packages. `configuration.py` owns source defaults and private `.env` resolution; redact the robot address from status, proxied JSON, errors and SSE. Jetson speech is observation only by default. Host health comes from `submission/host_health.py` (standard library, shared with `course.py`, appended to the path, never `course.py` itself, which re-executes into HIM's venv) every 5 s. `simulation.py` counts `late_state` events per run and keeps HIM's `Policy abort:` line (plain text), or a saved run's `summary.json` `him_reason`.
- `feeds.py` collects services independently. Speech uses status plus a heartbeat-bearing SSE stream, bounded history, reconnect deduplication and reset on service instance changes. Quiet speech is Idle, not Offline. Sensors use actual device health; clear stale cloud layers independently. Binary samples share short caches; measurements are never cached.
- Sensor pages are extracted as literals from our existing scripts, without importing their hardware dependencies. Three.js is an external pinned/hash-checked dependency installed locally by `setup_assets.py`, not copied into tracked source. Preserve single ownership of sensor devices; use shared topic readers when another node owns them.
- `simulation.py` reads our Docker JSON stdout because HIM's sim container has no network. Fresh view frames determine live status. Container ID and start time distinguish runs; a bounded nonblocking queue keeps rendering out of the control path. Home's diagnostics row names the run's avoidance filter, person detector and loop from their `started` events, forgotten on each new run. Log/data formats: [[sim-run-logs]].
- `rerun_worker.py` runs in the testground environment and reuses `submission/lidar_view.py`'s `Recording`, with bounded trails and a 200 MB server buffer. It starts on data arrival, uses dynamic loopback ports and stops with the hub. `recording` sources read saved run JSON lines (frames and events interleaved by wall time) or `.rrd` exports and stay Replay when paused or complete.
- `runs.py` lists the main checkout's `runs/` (`HARP_RUNS_DIR`) newest first from `run.json`, `summary.json` and `events.jsonl` started events, cached by file times (175 runs: 0.07 s cold). The Runs page opens a run by folder name only (matched to the run-name pattern, never a path) as a `recording` source with id `run-` plus a hash; at most `MAX_OPEN` (2) at once, the oldest closing first, since each holds a Rerun worker. Only Replay and Compare add sources (Compare one per run not already open; reopening one only moves it to the newest); Close or a hub restart removes them, since the open list is kept in memory only. Configured sources are never closed from that page. Its list redraws only when it changes, so focus and pointer stay put. Compare puts two independent replays side by side: their timelines are not synced. `runs.timing()` (`/api/runs/timing?name=`) reads one run's `policy` events (`timing`, `late_state`) on a clock starting at the policy's first line, and `run.json` `host_memory.seconds` within that window (samples before it are left out, so the chart's scale matches what it draws); `timing.js` draws it as inline SVG, loaded before `app.js`. A row's Timing link shows only when `events.jsonl` has a `timing` line (32 of 175 runs, 2026-11-09).
- `diagnostics.py` proxies Rerun assets and gRPC-web through the hub. Rerun 0.41 accepts only the root `/proxy` URI, so the embedded page scopes fetches to its source route. Buffer rewritten POST bodies into ArrayBuffers: a Request body stream makes Chrome require HTTP/2 and fail on this HTTP/1 server. Quiet streams have no data timeout; cancel them on client disconnect/shutdown and handle incomplete HTTP reads normally.
- `robot` sources poll `/status` and are drawn by the hub (`robot.js`), never embedded or proxied; `robot_feeds()` turns reading ages into feeds ([[robot-status]]).
- `him` checks the existing local viewer's HTML, not frame activity; paused pages stay Ready. The iframe talks directly to HIM's loopback server. Discovery sends no Start request, and hub shutdown does not stop HIM. This source has no remote proxy.
- `app.js` owns hash routes and availability ordering. Home's tiles (`tiles` in `app.js`, one entry per source kind) read only what each source's `status()` carries (`detail`: speech's `/api/status`, sensors' calib and stats; for runs, `simulation.py`'s per-run tally of the latest loop or goal event, hold, lidar lost, talks, people noticed and sim time), so a new chip starts in the source's status. Tiles stay in configuration order and are rebuilt only when the set of reachable sources changes. Reorder existing Home rows without losing keyboard focus. Closed views stop browser image polling, not collectors. After a hub restart, open the view in a new tab: a reloaded tab kept showing the previous Rerun recording (Chrome-based pane, 2026-11-09). Full-window views retain Home navigation and offline covers; one dead source must not disable other sources.

Limitations: our diagnostic exporter starts for simulation world runs, not plain planned moves. It does not export the simulated camera cloud; simulated depth is a point cloud rather than the real camera's depth image, and simulated RGB is absent. Do not invent those feeds or mix simulation and robot frames.

Verified: service isolation/restarts and redaction tests, local assets without internet, desktop/phone layouts and navigation, saved Rerun run/capture playback (tracks, detections and status panel in the `crossing` and `people` replays), the Runs list and Compare, the Timing page (desktop and phone), and actual HIM replay embedding without control requests. Real PC2 end-to-end operation, live simulation overhead, remote browser access and a full scored run with the new layers (all three 2026-11-09 runs stopped on deadlines) remain unverified.
